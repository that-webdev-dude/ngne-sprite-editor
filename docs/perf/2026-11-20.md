# Reference measurements for `@ngne/core` 0.4.0: 2026-11-20

The owner's run on branch `chore/ngne-0.4.0` ([issue #11](https://github.com/that-webdev-dude/ngne-sprite-editor/issues/11)),
the move from 0.3.0 to 0.4.0, on the final code, alone: no other benchmark or E2E ran at the
same time. Records written 11:24–11:31 UTC.

Environment: Windows 11 10.0.26200, i7-12650H (16 logical processors), 16 GB RAM; installed
Chrome 157.0.8103.80 (new headless), Node 24.15.0. Intel UHD (gen-12lp) and RTX 4060 Laptop
GPU (nvidia/lovelace); every browser benchmark verified the requested WebGPU adapter. These
are reference-hardware measurements, not SwiftShader.

Method: the unchanged [benchmark scripts](../../tests/perf/README.md), one process at a time,
`PERF_RECORD=1`, `PERF_GPU=intel-uhd` / `rtx-4060`, no `PERF_ID`: each record replaces or
creates the benchmark's own record. The CPU benchmark ran once without `PERF_GPU`.

## RTX 4060 cold load over budget

The largest of the 10 loads is the first one, at 2368 ms; their median is 756 ms (checkpoint E:
843 ms). In that load, DOMContentLoaded comes at 130 ms and the first paint at 2500 ms: the
page waits for Chrome's GPU process to start.

- **Startup traces**, all processes: `eglInitializeFn` (the GL display start in the GPU
  process, on the RTX 4060) takes 2346 ms cold with 0.4.0 and 2373 ms with 0.3.0. A blank page
  with no app takes 2325 ms cold and 616 ms warm. On Intel UHD, the blank page's first
  animation frame comes at 41–77 ms.
- **Report-only alternation:** 13 runs of 10 loads, in the order 0.4.0, 0.3.0, 0.3.1, 0.4.0,
  0.4.0, 0.3.1, 0.3.0, 0.3.0, 0.4.0, 0.3.1, 0.3.1, 0.4.0, 0.3.0.

| Version | Runs | Largest load per run | Median of all loads |
| ------- | ---- | -------------------- | ------------------- |
| 0.3.0 | 4 | 2448 / 1388 / 1381 / 1391 ms | 827 ms |
| 0.3.1 | 4 | 2401 / 1371 / 1444 / 1388 ms | 824 ms |
| 0.4.0 | 5 | 2438 / 1399 / 1382 / 1359 / 1431 ms | 811 ms |

  The load over 2 s was the first load of each of the first three runs, one per version; no
  later run had one. The time from the first animation frame to interactive was steady on all
  three versions (medians 322, 330 and 309 ms).
- **No app or engine code runs before that first paint:** the app renders nothing until its
  WebGPU adapter check resolves, and NGNE starts only once a viewport mounts.
- **Likely mechanism, not verified:** the discrete GPU powers down while the benchmark builds,
  and the next Chrome launch pays its wake-up cost.

Verdict: a machine effect, not the editor and not the engine. The 2 s budget is kept, and the
record stays as measured. Not explained: the loads of about 1.3–1.4 s that recur on every
version.
